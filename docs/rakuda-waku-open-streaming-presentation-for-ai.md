## 2. 「らくだ枠」とは何か（現状の技術・運用）

### 2.1 概念

**らくだ枠** = `https://rakuda.coffee/` 上で、LIVE配信（主に TikTok / YouTube / Instagram 等）と **同時に視聴者・参加者が遊ぶための Web 居場所**。

- 配信の「土台」は YouTube 等（世界中に多数）
- **らくだ枠** = 配信中・配信直後に **サイト側で一緒に遊ぶレイヤー**
- 文字パズル・三十（30人卓ゲーム）・連絡帳・ペア探し等

### 2.2 配信モード（`streamMode`）— 現状

| 項目 | 内容 |
|------|------|
| **効果** | 広告OFF・軽量化・掲示板更新間隔を長くする・viewer 購読停止等 |
| **ON の方法** | 管理画面（連絡帳「かんり」）での切替 ＋ URL `?stream=1`（ブックマーク用） |
| **現状** | **実質らくださん（管理者）中心** — 一般配信者向けの自助 ON UI は未整備 |
| **目的** | YouTube LIVE 等の **回線・端末負荷を下げ、配信を安定させる** |

参照：`src/lib/rakudaStreamMode.ts`／ `src/hooks/useAppShell.ts`

### 2.3 既存ルール（2026-05-27 記録・譲れない）

配信・枠に関わる人は：

- **煽らない**
- **子ども主役**
- **競争しない**

**線引き**：枠を独占したがる・悪口を平気で口にする人は **らくだ枠に会わせない。迷わずブロック**。

成長より **空気を守る** を優先。インフルエンサー LIVE は手段の一つだが、**上記に合う人だけ**。

## 5. 提案の詳細（構想レベル）

### 5.1 オープン化のイメージ

| 項目 | 案 |
|------|-----|
| **誰が** | ルールに合意した **任意の配信者** |
| **何を** | 配信モード付き URL（例 `?stream=1`）＋遊び方の案内 |
| **収益** | 配信プラットフォーム（YT/TikTok等）の **SC・ギフト等は100%配信者** |
| **らくだの取り分** | **0%**（サイト内寄付モデルとは別軸） |
| **期待値** | 「開発中・修正多し・LIVE中に不具合があり得る」を **事前同意** |
| **審査** | 全面自動公開 vs 招待制 vs 簡易申請 — **未決** |

### 5.2 らくださんが望む状態

```
24時間、誰かが「らくだ枠＋外部LIVE」で
子どもたちが静かに遊べる時間帯が増える

→ らくだ一人の配信負荷を分散
→ AU・口コミ・「無視できない実体」への寄与
```

### 5.3 寄付転換構想との関係

| 軸 | 寄付転換（別資料） | らくだ枠オープン（本資料） |
|----|-------------------|---------------------------|
| サイト収益 | 大人の寄付・コスト開示 | 取らない（配信者100%） |
| 目的 | 持続可能性・正直な鏡 | **利用拡大・配信分散・居場所の時間** |
| 矛盾？ | 表向きは矛盾しうる | **「枠は無料で開く／運営費は寄付」** の二層説明が必要 |

## 6. 想定メリット（らくださん・豆の仮説）

1. **24時間カバレッジ** — 一人配信の限界を超える
2. **LIVE相乗効果** — 伸びる時間帯を複数配信者で増やす
3. **差別化** — 「配信しながら一緒に遊べるサイト」は TikTok 単体と被らない
4. **実体成長** — 企業・自治体が無視しにくい「常に動いている居場所」
5. **世界観拡張** — 合う配信者が **同じ空気** を広げる担い手になる
6. **収益をライバーに** — 配信者インセンティブ（SC・ギフト）を奪わない → 参加しやすい

## 7. 想定リスク（豆が先に挙げる — 他AIに深掘りしてほしい）

| リスク | 内容 |
|--------|------|
| **子ども安全** | 未知の配信者経由で不適切発言・リンク・誘導 |
| **モデレーション** | ワンオペで **ブロック・通報対応** が追いつくか |
| **世界観の希薄化** | 合わない配信者が「らくだ枠」を使うと **空気が壊れる** |
| **技術的不安定** | 修正中に LIVE 中障害 → **配信者・視聴者の不信** |
| **Firebase / 3GB** | 同時接続増で **重さ・落ち** — 三十満室設計との両立 |
| **ブランド** | トラブルが「らくだ珈琲」名義で拡散 |
| **法務** | 配信者の利用規約・免責・13歳未満・特商法との関係 |
| **収益** | サイト寄付モデルと「全部ライバー」の **説明コスト** |
| **配信者の「口出し」** | 支援・人気配信者が **運営に口を出す**（他AI盲点と共通） |
| **独占・煽り** | 枠を取り合う・ランキング煽り配信 |
| **燃え尽き** | 審査・オンボーディング・トラブル対応が **らくださんに集中** |

## 8. やらないこと（他AIも提案しないでほしい）

- らくだ枠利用で **サイト内課金・抽成**（本構想では）
- 配信者ランキング・ **煽り型** 視聴者競争
- 子ども安全より **人数優先**
- ルール違反者を **収益理由で放置**
- URL 変更・別ドメイン分割

## 9. 他AIへの質問（詳細版）

### A. 進めるべきか

1. **全面オープン** vs **招待制** vs **申請＋簡易審査** — 397 AU・ワンオペ条件下で **どれが最適** か？
2. 「みんなが遊んでくれたらうれしい」だけでは足りない — **成功条件（KPI）** を何に置くべきか？
3. らくださん一人のLIVE実績（同接200前後）を **再現可能なオンボーディング** に落とせるか？

### B. 危険・安全

4. **子どもが主役** のまま、第三者配信者を許すときの **必須ガードレール**（技術・規約・運用）Top 5は？
5. 「迷わずブロック」ルールを **スケール** させる方法（コミュニティモデレーション等）は世界観を壊さず可能か？
6. LIVE中の **不具合** が配信者の炎上に繋がるリスク — **事前同意文** に何を書くべきか？

### C. 収益100%ライバー

7. 配信収益0%取り分は **配信者参加** には効くが、**らくだのサーバー代** は誰が払うか — 寄付モデルと **矛盾なく説明** する文案は？
8. 将来「大口配信者だけ優遇」が自然に発生しないか — **防止策** は？

### D. プラットフォームとの関係

9. YouTube / TikTok / Instagram 単体配信 vs **らくだ枠併用** — 配信者にとっての **メリット1文** は？
10. 「LIVE中・直後だけ伸びる」を **最大化** する導線（URL・QR・プロフィール固定）のベストプラクティスは？

### E. 段階的展開

11. **Phase 0〜3**（例：知人1人 → 5人 → 20人 → 公開）の具体案。
12. 各 Phase の **最長期間** と **撤退条件**（世界観が壊れたら止める等）。

### F. 豆向け

13. 配信モードを **一般配信者が自助でON** する際の **技術的最小セット** は？
14. 三十・Firebase 同時負荷 — **1配信あたりの安全な同接上限** の考え方は？

## 10. 豆が他AIに特に聞きたいこと

> **「収益は全部ライバー」** と **「運営は寄付で持つ」** を、  
> 配信者・視聴者・大人に **誤解なく** 伝える構造は可能か？

> **不安定な開発中サービス** をオープンにした **前例**（成功・失敗）から、  
> らくだ枠向けの **期待値コントラクト**（利用規約・口頭・サイト表示）を提案してほしい。

> らくださんの **ブロック基準**（煽らない・子ども主役・競争しない）を、  
> **事前スクリーニング** に落とす **質問3つ** だけにするとしたら何か？
