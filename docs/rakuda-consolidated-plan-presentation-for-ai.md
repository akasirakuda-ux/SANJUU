## 4. 統合構想 — お金の4本柱

```
① 配信プラットフォームの収益（SC・ギフト・YouTube等）
   → 100% ライバー。らくだは一切取らない。

② らくだ枠の利用（LIVE併用含む）
   → 無料。ライバーに利用料・寄付ノルマは課さない。
   → オープン化：誰でも使ってよい（普段通り。特別な招待制イメージなし）。
   → 不安定さ（修正多し）を事前に承知してもらう。

③ サイト維持（応援・協賛・特別寄付）
   → 大人の責任。子どもには関係ない。
   → 同一 Stripe で扱う（別窓口は今は不要）。

④ 口コミ・紹介（年パスコード等）
   → 仕組みは残す。常用はしない。乱発しない。
```

### 4.1 ③の詳細 — 応援・協賛・特別寄付

| 項目 | 方針 |
|------|------|
| **サイト内広告** | **全面廃止**（青・茶・緑すべて） |
| **旧・緑¥480/月** | **廃止** |
| **応援サブスク** | **月150円以上・金額は利用者が選ぶ** |
| **特別寄付** | 100円以上・自由金額（既存 Payment Link） |
| **特典** | **金額に応じた優遇なし**。10万も150も遊び方同じ |
| **唯一の例外** | 名前・絵文字の **緑**（応援の意思表示。Pay-to-win ではない） |
| **協賛者** | 「より良い日本を子や孫の世代に残したい」と願う人。**法人・個人・業種不問** |
| **協賛と150円応援** | **同じ Stripe・同じ扱い** |
| **協賛者の名前** | **本人が選択**（載せる／載せない）。載せる場合は **大人向けページのみ** |
| **子ども画面** | お金の話・協賛者名・コスト開示 **一切出さない** |

### 4.2 大人向けコスト開示（一石）

**意図**：見て見ぬふりの大人に **事実** を見せる（guilt 煽りではない）。

掲載例（目安・手入力更新）：

- 28日の利用者数
- 今月の応援・協賛（人数／合計）
- 固定費：サーバー（Firebase等）・ドメイン・**Cursor Pro+（開発）** 等
- 不足分 → らくだが自己負担

**子どもには関係ない。無理に払う必要はない。**

### 4.3 ④ 年パス（感謝の1年無料パス）

| 項目 | 方針 |
|------|------|
| **仕組み** | **残す**（コード発行・紹介者記録・既存利用者） |
| **今後** | 使う機会は **少なくなるかも**。乱発しない |
| **「紹介者」** | 誰がコードを配ったかの記録（2026-06-01「紹介の鎖」）— **協賛者名とは別** |
| **収益** | 無料（Stripe 課金ではない） |

## 7. らくださんの動機（要約）

- お金の焦り（ヤケ）がある。自分でも **無茶かも** と思っている
- それでも **中途半端な配信・判断** が一番気持ち悪い
- **何も売りがないサイト** より **はっきりした特徴** を持ちたい
- 利用者がいるのに寄付が集まらない現実を、**払う気のある大人** に見せたい
- 腹の立つ対象：**行目のサーバー代** より **お金がないと生きられない構造**

## 10. 他AIへの質問（詳細）

### A. 統合構想全体

1. 4本柱を **一般の視聴者・ライバー・協賛者** に誤解なく伝える **文案1段落** を書いてほしい。
2. 旧北極星（月100万安定・3〜6ヶ月→広告OFF）を **前倒しで広告OFF** した場合のリスク評価。
3. ワンオペ・397 AU で **全部同時に** やる場合の **破綻ポイント** はどこか？

### B. 応援・協賛・開示

4. 150円以上可変サブスク — Stripe手数料を踏まえた **最低額の勧告** は？
5. 協賛者名「本人選択」— **デフォルト** は載せる／載せないどちらがよいか？
6. コスト開示に **Cursor Pro+** を載せる是非（透明性 vs 雑音）。
7. 「より良い日本を子や孫に…」という **協賛フレーミング** — 刺さる／刺さらない層の分析。

### C. らくだ枠オープン

8. 「普段通り」オープン vs 段階的 — 397 AU・ワンオペで **推奨** は？
9. 配信者向け **事前同意文** の必須条項 Top 5。
10. ライバーが「寄付で成り立っている」と言う **頻度・場面** のガイドライン案。

### D. 年パス・紹介

11. 年パスを残しつつ寄付中心へ — **既存感謝パス利用者** との整合。
12. 「紹介の鎖」（口コミ）と **協賛** を **同じ人** に求めすぎない線引き。

### E. 30日・90日

13. 実装優先順位 Top 5（広告停止／Stripe／開示／ライバー向け同意／特商法 等）。
14. 収益ゼロ期間の **KPI**（1人目の応援以外に何を見るか）。
15. 燃え尽き防止 — らくださん **週あたり** の配信・開発上限の目安。

### F. 豆向け

16. 150以上可変サブスクの **Stripe 最小実装** パターン。
17. 協賛者名の opt-in を **Firestore / Stripe metadata** で持つ設計案。
